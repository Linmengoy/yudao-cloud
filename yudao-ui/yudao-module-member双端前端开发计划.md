# yudao-module-member 双端前端开发计划

## 1. 计划定位

本章节面向 `yudao-module-member` 在两个前端项目中的第一阶段落地：

```text
draw2video-admin   管理端，负责会员运营管理
draw2video-client  用户端，负责会员注册登录、Token 生命周期、用户资料和账号安全
```

管理端重点是“会员运营管理”，不承担普通会员登录注册；后台登录仍走 `system/auth`。

用户端重点是“会员注册登录、Token 生命周期、用户资料、账号安全”，直接对接 `/app-api/member/*`。

member 是 AIGC MVP 闭环入口：

```text
注册登录 → 用户资料 → 钱包 → 模型选择 → 生成提交 → 任务进度 → 资产沉淀
```

## 2. 模块边界

管理端 member 边界：

- 面向运营、平台管理员、租户管理员
- 管理会员用户资料、状态、标签、分组、等级、积分、余额入口、成长值、签到、地址等会员运营信息
- 不使用 `/member/auth/*` 做后台登录
- 后台管理员认证继续使用 `/system/auth/*`
- 会员新增默认由用户端注册产生，管理端第一阶段不做代注册

用户端 member 边界：

- 面向普通用户、创作者
- 承担邮箱验证码注册、手机号验证码登录即注册、手机号密码登录
- 承担 Token 保存、刷新、退出登录、登录态恢复
- 承担用户资料展示与基础资料修改
- 替换当前 mock auth，接入真实 member 接口

## 3. 用户端接口范围

用户端会员认证接口：

```text
POST /app-api/member/auth/send-email-code
POST /app-api/member/auth/validate-email-code
POST /app-api/member/auth/email-register
POST /app-api/member/auth/login
POST /app-api/member/auth/sms-login
POST /app-api/member/auth/send-sms-code
POST /app-api/member/auth/validate-sms-code
POST /app-api/member/auth/refresh-token
POST /app-api/member/auth/logout
GET  /app-api/member/user/get
PUT  /app-api/member/user/update
```

用户端 P1 账号接口：

```text
PUT /app-api/member/user/update-password
PUT /app-api/member/user/update-email
```

邮箱密码登录、邮箱找回密码如果后端补齐后再接入。

## 4. 管理端接口范围

管理端会员管理接口：

```text
GET /admin-api/member/user/page
GET /admin-api/member/user/get?id=
PUT /admin-api/member/user/update
PUT /admin-api/member/user/update-level
PUT /admin-api/member/user/update-point
```

管理端 API 文件内仍只写业务路径，不写 `/admin-api`：

```text
src/api/member/user/index.ts
  ├── /member/user/page
  ├── /member/user/get?id=
  ├── /member/user/update
  ├── /member/user/update-level
  └── /member/user/update-point
```

## 5. 用户端开发计划

阶段 1：API 与类型封装。

- 新增 `src/features/auth/auth-api.ts`，封装 `member/auth` 全部接口
- 新增 `src/features/auth/auth-types.ts`，定义认证请求和响应类型
- 新增 `src/features/profile/profile-api.ts`，封装 `member/user/get`、`member/user/update`
- 新增 `src/features/profile/profile-types.ts`，定义会员用户资料类型
- 复用现有 `src/lib/api-client.ts` 的 token、refresh-token、401 重试能力
- 不再另写 fetch 客户端

建议类型：

```text
LoginToken
MemberUser
EmailRegisterReq
SmsLoginReq
PasswordLoginReq
UpdateProfileReq
```

阶段 2：Auth Store 真实化。

- 改造 `src/features/auth/auth-store.tsx`
- 移除 `loginMock` 作为主流程
- 登录、注册成功后保存 `accessToken`、`refreshToken`、`expiresTime`
- 登录、注册成功后拉取当前用户资料
- 刷新页面时恢复 token 和用户信息
- refreshToken 失效后清理登录态并打开登录弹窗

Auth Store 状态：

```text
AuthState
  ├── user
  ├── accessToken
  ├── refreshToken
  ├── expiresTime
  ├── isAuthenticated
  ├── isInitializing
  ├── isLoginModalOpen
  ├── authMode
  └── redirectTo
```

Auth Store 方法：

```text
loginByPassword(mobile, password)
loginBySms(mobile, code)
registerByEmail(req)
sendSmsCode(scene, mobile)
sendEmailCode(scene, email)
validateEmailCode(scene, email, code)
fetchUser()
logout()
openLoginModal(mode, redirectTo)
closeLoginModal()
```

阶段 3：登录注册 UI。

- 改造 `src/features/auth/AuthModal.tsx`
- 从“开发模式 mock 登录”升级为真实登录注册弹窗
- 支持手机号验证码登录、邮箱注册、密码登录
- 支持 loading、错误、成功、禁用状态
- 支持登录成功后回到原始目标页面

建议组件：

```text
src/features/auth
  ├── AuthModal.tsx
  ├── auth-tabs.tsx
  ├── login-form.tsx
  ├── register-form.tsx
  ├── forgot-password-form.tsx
  ├── sms-code-button.tsx
  └── email-code-button.tsx
```

阶段 4：独立登录注册页。

- `/login` 不再只是打开弹窗，应具备完整页面兜底能力
- 新增 `/register` 页面，复用注册表单
- `/forgot-password` 第一阶段可预留入口
- 支持 `redirect` 参数，登录成功后回到目标页面

阶段 5：登录态守卫。

- 未登录访问工作台时打开登录弹窗或跳转登录页
- 未登录访问生成、钱包、任务、资产、个人中心时触发登录引导
- 生成提交前未登录时打开登录弹窗
- 登录成功后继续原操作流程
- 退出登录后清理 token、user、wallet、任务和资产私有缓存

阶段 6：用户资料页。

- 改造 `src/app/(app)/profile/page.tsx`
- 替换硬编码占位信息
- 展示真实头像、昵称、手机号、邮箱、账号状态
- 第一阶段支持昵称和头像修改
- P1 支持修改密码、绑定邮箱、换绑手机号

建议组件：

```text
src/features/profile
  ├── profile-api.ts
  ├── profile-types.ts
  ├── profile-form.tsx
  ├── avatar-uploader.tsx
  └── account-security-panel.tsx
```

阶段 7：与 AIGC 业务联动。

- 生成提交前判断登录态
- 钱包、任务、资产接口请求统一走带 token 的 API 客户端
- 登录成功后刷新用户资料和钱包余额
- 退出登录后清理用户私有业务缓存

## 6. 用户端界面计划

登录注册弹窗：

- 桌面端居中弹窗，宽度建议 `420px-480px`
- 移动端使用全屏页或底部 Sheet，避免键盘遮挡
- 顶部展示品牌名和简短说明，例如“登录后即可保存作品、查看任务进度和资产”
- Tab 包含手机号验证码登录、邮箱注册、密码登录
- 底部展示用户协议、隐私政策、登录即表示同意等合规文案
- 移除“开发模式”提示文案

手机号验证码登录界面：

- 字段顺序为手机号、验证码、主按钮
- 主按钮文案使用“登录 / 注册”
- 验证码按钮支持发送中、倒计时、重新发送、频控状态
- 手机号格式错误时验证码按钮不可点击
- 提交中展示 loading，避免重复提交
- 登录成功后关闭弹窗并跳转到原始目标页面

邮箱注册界面：

- 字段顺序为邮箱、邮箱验证码、密码、确认密码、邀请码、协议勾选
- 邀请码可折叠或弱化展示
- 密码框支持显示和隐藏密码
- 密码规则常驻轻提示：`8-32 位，至少包含字母和数字`
- 协议未勾选时注册按钮不可提交或提交时明确提示
- 注册成功后显示短暂成功状态：“注册成功，正在进入工作台”

密码登录界面：

- 字段顺序为手机号、密码、登录按钮
- 提供“忘记密码”入口，P1 未完成前可置灰或跳转说明页
- 错误提示区分手机号格式错误、密码为空、账号或密码错误、账号被禁用
- 不在 URL、Toast、控制台中展示密码或 token

独立登录注册页：

- `/login`、`/register` 具备完整页面能力
- 桌面端采用左右分栏
- 左侧展示产品价值、作品保存、任务进度、资产中心、积分钱包等卖点
- 右侧展示登录或注册表单卡片
- 移动端采用单列表单，顶部保留 Logo 和返回首页

个人中心页面：

- 顶部用户卡片展示头像、昵称、手机号、邮箱、账号状态
- 基础资料卡片展示昵称、头像、性别、地区、生日
- 账号安全卡片展示手机号、邮箱、密码、安全提醒
- 操作区提供保存资料和退出登录
- 头像必须有默认 fallback
- 手机号、邮箱默认脱敏展示
- 未绑定邮箱时展示“未绑定”状态和引导
- 资料保存成功后使用轻提示，不强制刷新页面
- 退出登录按钮放在安全区或页面底部，并使用二次确认

登录态守卫界面：

- 未登录访问工作台时展示登录引导，不展示空白页
- 登录引导标题：“登录后继续创作”
- 登录引导说明：“登录后可保存作品、查看任务进度和资产”
- 主按钮：“登录 / 注册”
- 从生成提交触发登录时，登录成功后回到原操作流程

表单状态设计：

- 默认态
- 聚焦态
- 错误态
- 禁用态
- loading 态
- 成功态
- 字段级错误优先展示在字段下方
- 接口级错误展示在按钮上方或 Toast

移动端适配：

- 输入框高度不低于 `44px`
- 验证码输入框和按钮在窄屏下可上下排列
- 登录注册弹窗在小屏下改为全屏页或底部 Sheet
- 个人中心卡片在移动端单列展示

## 7. 管理端开发计划

阶段 1：现有会员用户能力补强。

- 保留现有 `src/views/member/user/index.vue` 主列表
- 补齐用户编号、昵称、手机号、邮箱、注册时间、登录时间、状态、等级、标签、分组筛选
- 表格补充邮箱、邮箱验证状态、注册来源、最近登录 IP、AIGC 用户标识等字段
- 手机号和邮箱默认脱敏展示
- 用户状态使用 Tag 展示

阶段 2：会员详情页补强。

- 扩展 `src/views/member/user/detail/index.vue`
- 顶部概要卡展示头像、昵称、用户编号、状态、注册时间、最近登录
- 左侧基础信息展示手机号、邮箱、性别、地区、生日、标签、分组、备注
- 右侧账户信息展示积分、成长值、余额、冻结余额、等级
- 下方 Tab 展示积分记录、余额记录、成长值、签到、地址、AIGC 任务、AIGC 资产
- AIGC 任务、资产、钱包流水支持按 userId 跳转筛选

阶段 3：会员编辑与风控操作。

- 继续使用 `src/views/member/user/UserForm.vue`
- 第一阶段保留“不新增会员”，会员由用户端注册产生
- 可编辑昵称、头像、真实姓名、性别、生日、地区、标签、分组、备注、状态
- 手机号、邮箱不建议普通编辑
- 禁用会员、修改积分、修改等级、修改余额必须二次确认
- 敏感信息不展示密码、验证码、token

阶段 4：权限完善。

- 补齐详情按钮、详情页编辑按钮权限控制
- 按钮权限继续使用 `v-hasPermi`
- 菜单组件路径必须与 `src/views/member/user` 下文件匹配

建议权限：

```text
member:user:query
member:user:update
member:user:export
member:user:update-status
member:user:update-level
member:user:update-point
member:user:update-tag
member:user:update-group
pay:wallet:update-balance
promotion:coupon:send
```

阶段 5：管理端 member/auth 边界确认。

- 不新增用于普通会员登录的 `src/api/member/auth`
- 管理端后台登录保持 `src/api/login/index.ts` 的 `system/auth`
- 如需运营代注册会员，应独立设计“创建会员”后台接口
- 如需代用户重置手机号或邮箱，必须后端提供审计记录和权限控制

- 操作按钮采用“详情、编辑、更多”结构，更多内放修改等级、修改积分、修改余额、发送优惠券、禁用/启用

会员详情页：

- 顶部概要卡展示头像、昵称、用户编号、状态、注册时间、最近登录
- 顶部固定关键操作：编辑资料、调整等级、调整积分、禁用/启用
- 左侧基础信息展示手机号、邮箱、性别、地区、生日、标签、分组、备注
- 右侧账户信息展示积分、成长值、余额、冻结余额、等级

修改等级、积分、余额界面：

- 使用独立小弹窗
- 展示当前值和调整后值
- 必填调整原因，便于审计
- 危险操作二次确认
- 成功后刷新列表和详情页局部数据

筛选与批量操作：

## 9. 双端统一设计规范

字段展示：

- 手机号展示为 `138****8888`
- 邮箱展示为 `u***@example.com`
- 空值统一显示 `--`
- 时间统一显示到分钟，例如 `2026-05-27 14:30`
- 状态统一使用 Tag 或 Badge，不只用纯文本
- 金额、积分等数值格式化，重要数值右对齐

反馈规范：

- 保存成功使用轻 Toast
- 删除、禁用、调整余额使用确认弹窗
- 表单错误展示在字段下方
- 接口错误保留后端错误含义，但转换成用户可理解文案
- loading 使用按钮级 loading 和页面局部骨架屏

敏感信息规范：

- 用户端不展示 token、验证码、密码
- 管理端默认脱敏手机号、邮箱
- 管理端如需查看完整手机号或邮箱，应有专门权限和审计
- 任何端都不在控制台输出认证响应完整对象

可访问性：

- 表单项必须有明确 label
- 错误文案靠近对应字段
- 按钮禁用时要能看出原因
- 键盘回车可提交登录表单
- 验证码按钮和登录按钮在 loading 时不可重复点击

## 10. 联调顺序

用户端联调顺序：

```text
1. 邮箱验证码发送
2. 邮箱验证码注册
3. 注册成功保存 token
4. 注册成功拉取当前用户
5. 手机号验证码发送
6. 手机号验证码登录即注册
7. 手机号密码登录
8. Token 自动刷新
9. 退出登录
10. 用户资料展示
11. 用户资料修改
12. 生成、钱包、任务、资产模块验证登录态联动
```

管理端联调顺序：

```text
1. 会员列表分页、筛选、重置
2. 会员详情页基础信息
3. 会员编辑保存
4. 修改等级
5. 修改积分
6. 修改余额入口
7. 会员状态调整
8. 标签、分组筛选与编辑
9. 按钮权限验证
10. 动态菜单路由验证
11. 手机号、邮箱脱敏验证
```

## 11. 验收标准

用户端验收：

- 新用户可通过邮箱验证码完成注册
- 邮箱注册成功后自动登录并进入工作台
- 新用户可通过手机号验证码登录即注册
- 老用户可通过手机号密码登录
- 刷新页面后仍能保持登录态
- accessToken 过期后可自动刷新
- refreshToken 失效后清理登录态并打开登录弹窗
- `/profile` 展示真实会员资料
- 用户可修改昵称和头像
- 退出登录后无法访问工作台、钱包、任务、资产、个人中心
- 密码、验证码、token 不出现在 URL、页面日志、控制台输出中
- 登录注册表单具备 loading、错误、成功、禁用状态
- 登录注册界面在移动端可正常使用

管理端验收：

- 会员列表展示真实会员数据
- 可按昵称、手机号、注册时间、等级、标签、分组筛选
- 会员详情展示基础信息、账户信息、积分、余额等记录
- 运营可编辑允许修改的会员资料
- 修改等级、积分、余额有权限控制和二次确认
- 邮箱、手机号等敏感信息按规则脱敏
- 详情、编辑、状态、积分、等级、余额等按钮权限生效
- 动态菜单能正确加载会员用户列表和详情页
- 管理端不暴露会员密码、验证码、accessToken、refreshToken
- 列表、详情、编辑弹窗具备空状态、异常状态、无权限状态
