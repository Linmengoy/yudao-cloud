# 客户端站内信技术方案

## 背景

`draw2video-client` 是面向会员用户的 Next.js 创作客户端。当前后端已有 `system_notify_message`、站内信模板、站内信发送服务和管理端站内信接口，但管理端接口固定按管理员用户读取，不适合客户端会员用户直接复用。

本方案将站内信能力打通为“会员端 App API + 客户端通知中心”的完整链路。

## 当前差异

- 前端原方案调用 `/app-api/member/notify-message/*`，后端不存在对应 Controller。
- 后端已有 `/system/notify-message/*` 管理端接口，但内部固定使用 `UserTypeEnum.ADMIN`。
- 后端已有 `NotifyMessageService`、`NotifyMessageMapper` 和 `NotifyMessageDO`，可以直接复用用户归属、分页、未读数、已读更新能力。
- 客户端需要会员用户消息，因此后端必须固定使用 `UserTypeEnum.MEMBER`。

## 建设目标

- 新增会员端站内信 App API，路径统一为 `/app-api/system/notify-message/*`。
- 会员端接口只返回当前登录会员自己的站内信。
- 前端通知中心对接真实后端路径、参数和字段。
- 前端保留统一的 `NotificationItem` 视图模型，通过 API 层完成后端 DTO 映射。
- 不新增数据库表，不复制站内信业务逻辑，不引入新的前端状态管理库。

### 新增位置

### 会员端接口

```txt
GET /system/notify-message/my-page?pageNo=1&pageSize=20&readStatus=false&templateCode=task&templateType=2
```

获取当前会员站内信分页，支持按已读状态、模板类型、模板编码和创建时间筛选。内部固定传：

```java
getLoginUserId(), UserTypeEnum.MEMBER.getValue()
```

---

```txt
GET /system/notify-message/get?id=1
```

获取当前会员站内信详情。服务端必须校验 `userId` 和 `userType`，避免越权读取。

---

```txt
GET /system/notify-message/get-unread-count
```

获取当前会员未读数。返回后端原始数据为 `Long`。

---

```txt
GET /system/notify-message/get-unread-list?size=10
```

获取当前会员最新未读站内信列表。

---

```txt
PUT /system/notify-message/update-read?ids=1,2
```

标记当前会员指定站内信为已读。Mapper 已按 `userId + userType` 限制更新范围。

---

```txt
PUT /system/notify-message/update-all-read
```

标记当前会员全部站内信为已读。

## 后端响应模型

会员端响应保留后端站内信模板快照字段，避免客户端依赖管理端 VO。

```java
public class AppNotifyMessageRespVO {
    private Long id;
    private Long templateId;
    private String templateCode;
    private String templateNickname;
    private String templateContent;
    private Integer templateType;
    private Map<String, Object> templateParams;
    private Boolean readStatus;
    private LocalDateTime readTime;
    private LocalDateTime createTime;
}
```

不返回 `userId`、`userType`，避免暴露内部归属字段。

## 前端设计

### 前端接口

前端统一通过 `/app-api` 代理访问：

```txt
GET /app-api/system/notify-message/my-page
GET /app-api/system/notify-message/get
GET /app-api/system/notify-message/get-unread-count
GET /app-api/system/notify-message/get-unread-list
PUT /app-api/system/notify-message/update-read
PUT /app-api/system/notify-message/update-all-read
```

### 前端视图模型

```ts
export interface NotificationItem {
  id: number | string;
  title: string;
  content: string;
  type: NotificationType | string;
  read: boolean;
  important?: boolean;
  actionUrl?: string;
  actionText?: string;
  createdAt?: string;
}
```

### 字段映射

```txt
templateNickname || templateCode -> title
templateContent -> content
templateType -> type
readStatus -> read
createTime -> createdAt
templateParams.actionUrl -> actionUrl
templateParams.actionText -> actionText
templateParams.important -> important
```

`actionUrl` 必须只允许站内相对路径。

## 客户端功能

- 工作台侧边栏通知铃铛展示未读数。
- 通知中心支持全部、未读、系统、任务、资产、钱包、账号、活动筛选，其中业务分类通过 `templateCode` 模糊匹配。
- 支持分页、刷新、空状态、错误状态。
- 支持单条消息标记已读。
- 支持全部标为已读。
- 支持消息详情页。
- 点击业务跳转前触发已读。
- 未读数每 45 秒轮询，窗口聚焦时刷新。

## 安全要求

- 会员端接口必须使用当前登录会员 ID。
- 会员端接口必须固定 `UserTypeEnum.MEMBER`。
- 详情接口必须校验消息归属。
- 已读接口必须按 `userId + userType` 限制更新范围。
- 客户端不渲染 HTML 消息内容。
- 客户端只允许跳转站内相对路径。

## 验收标准

- 登录会员可以获取自己的站内信分页。
- 登录会员不能读取管理员或其他会员的站内信详情。
- 未读数接口返回真实当前会员未读数。
- 单条已读和全部已读会影响未读数。
- 前端通知铃铛、通知中心、详情页都能对接 `/app-api/system/notify-message/*`。
- 通知中心分类筛选可以真实下推到后端分页接口。
- `pnpm lint` 通过。
- `pnpm build` 通过。
- 后端 `yudao-module-system-server` 编译通过。

## 发布就绪检查

- 后端新增 `AppNotifyMessageController`、App VO、分页筛选能力，并完成编译验证。
- 前端站内信接口对接 `/app-api/system/notify-message/*`，并完成字段映射。
- 前端生产构建阻断问题已修复，发布前必须执行 `pnpm lint`、`pnpm build`。
- 生产模板建议统一 `templateCode` 前缀：`task`、`asset`、`wallet`、`account`、`activity`，以保证分类筛选命中。
- 生产模板可选配置 `templateParams.actionUrl`、`templateParams.actionText`、`templateParams.important`，用于展示跳转按钮和重要标记。
